# Endstate Diagram App Product Plan

> **Implementation gate:** This is a review plan only. I will not implement or deploy the app until you explicitly say to build it.

**Goal:** Build **Endstate**, a workspace-based diagram app for planning/analyzing a topic by mapping the relationship between a fixed **start node** and **end node**.

**Core idea:** A workspace contains projects. A project owns one primary diagram. A new diagram starts with both a start node and an end node already present. Users add any nodes and edges between or around them. Relationships are many-to-many through edges. A node may optionally represent another project/diagram; expanding it shows the linked project's diagram. Nodes and edges both support notes, edited in a modal WYSIWYG markdown editor and expandable as formatted text.

---

## Confirmed decisions

1. **Use workspaces** rather than single-user-only.
2. **Deploy to `https://endstate.ahsanworks.com`** when implementation is approved.
3. **No prerequisite concept.** The app is nodes + edges. Start and end nodes exist from the beginning.
4. **Notes exist on nodes and edges.** Notes edit in a modal WYSIWYG markdown editor and expand as formatted text.
5. **Edges are directed by default and for MVP.**
6. **Adding a node from an edge rewires `A -> B` into `A -> New -> B`.**
7. **Use a real WYSIWYG markdown editor dependency if one is not already present.**

---

## Product scope

### MVP

1. Workspace-based project list.
2. Each project has one diagram canvas.
3. New project starts with a **Start** node and **End** node already on the canvas.
4. Add, edit, move, and delete custom nodes.
5. Connect nodes with directed edges.
6. Support many-to-many node relationships.
7. Click an edge to open a small action menu:
   - Delete edge
   - Add node near/on this edge
   - Edit edge label
   - Edit edge notes
   - Expand/collapse edge notes preview
8. Node action menu:
   - Edit title/body
   - Edit notes
   - Expand/collapse notes as formatted text
   - Link to project/diagram
   - Delete node
9. Mark node type:
   - Start
   - End
   - Default
   - Linked diagram/project
10. Link a node to another project.
11. Expand linked node to preview/open that project's diagram.
12. Save/load diagrams.

### Explicitly skipped for MVP

- Real-time collaboration.
- AI generation.
- Version history.
- Advanced permissions beyond workspace membership.
- Multiple diagrams per project.
- True recursive embedded canvas inside a node.

Add these only after the workspace diagram workflow is useful.

## Mental model

Endstate is a graph canvas anchored by two fixed initial nodes:

```text
[Start State] ---- nodes + edges chosen by user ---- [End State]
```

There is no built-in prerequisite language. Users decide what each edge means using labels and notes. The app should not force “requires”, “depends on”, or “backwards planning” semantics into the UI.

---

## Data model

Keep it boring and relational.

```sql
workspaces (
  id TEXT PRIMARY KEY,
  name TEXT NOT NULL,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL
)

workspace_members (
  workspace_id TEXT NOT NULL REFERENCES workspaces(id) ON DELETE CASCADE,
  user_id TEXT NOT NULL,
  role TEXT NOT NULL CHECK (role IN ('owner','admin','member')),
  PRIMARY KEY (workspace_id, user_id)
)

projects (
  id TEXT PRIMARY KEY,
  workspace_id TEXT NOT NULL REFERENCES workspaces(id) ON DELETE CASCADE,
  name TEXT NOT NULL,
  description TEXT DEFAULT '',
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL
)

nodes (
  id TEXT PRIMARY KEY,
  project_id TEXT NOT NULL REFERENCES projects(id) ON DELETE CASCADE,
  title TEXT NOT NULL,
  body TEXT DEFAULT '',
  notes_markdown TEXT DEFAULT '',
  type TEXT NOT NULL CHECK (type IN ('start','end','default','linked_project')),
  x REAL NOT NULL,
  y REAL NOT NULL,
  locked INTEGER NOT NULL DEFAULT 0,
  linked_project_id TEXT REFERENCES projects(id) ON DELETE SET NULL,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL
)

edges (
  id TEXT PRIMARY KEY,
  project_id TEXT NOT NULL REFERENCES projects(id) ON DELETE CASCADE,
  from_node_id TEXT NOT NULL REFERENCES nodes(id) ON DELETE CASCADE,
  to_node_id TEXT NOT NULL REFERENCES nodes(id) ON DELETE CASCADE,
  label TEXT DEFAULT '',
  notes_markdown TEXT DEFAULT '',
  style TEXT NOT NULL DEFAULT 'directed' CHECK (style = 'directed'),
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL,
  UNIQUE(project_id, from_node_id, to_node_id),
  CHECK (from_node_id <> to_node_id)
)
```

Many-to-many is naturally supported because each node can have many incoming and outgoing edges.

Start/end nodes should be created automatically with `locked = 1` so the user can edit/move/annotate them but not accidentally delete them.

## Notes model

### Node notes

- Stored as markdown in `nodes.notes_markdown`.
- Edited from a modal WYSIWYG markdown editor.
- Node card shows a small notes indicator when notes exist.
- Expanded node displays rendered formatted text below the node title/body.

### Edge notes

- Stored as markdown in `edges.notes_markdown`.
- Edited from the edge click menu.
- Edge can show a notes indicator/label chip.
- Expanded edge shows a small formatted note popover or side panel.

### Editor recommendation

Use an already-installed markdown/WYSIWYG editor if available. If none exists, add one focused WYSIWYG markdown editor dependency; the user explicitly chose WYSIWYG over textarea + preview.

## UX flow

### New project

- User creates a project inside a workspace.
- Canvas opens with two nodes:
  - **Start** on the left
  - **End** on the right
- User adds nodes and edges freely.

### Node actions

From any node, user can:

- edit node content,
- edit notes,
- expand/collapse notes,
- connect to another node,
- link node to another project,
- open linked project preview,
- delete node unless it is locked start/end.

### Edge click menu

Clicking an edge opens a compact menu near the click point:

- **Add node here** — creates a node near the edge and rewires:
  - old: `A -> B`
  - new: `A -> New -> B`
- **Edit label** — sets relationship text.
- **Edit notes** — opens notes editor modal.
- **Expand notes** — renders formatted notes for review.
- **Delete edge** — removes only the relationship, not the nodes.

### Linked project node

A node can be changed to **Linked diagram** and assigned another project.

When collapsed:
- It behaves like a normal node.
- Shows a small linked-project badge.

When expanded:
- It displays a read-only preview of the linked project's diagram in a side panel.

MVP recommendation: use a side panel preview first. Embedded nested canvas can come later.

## Suggested implementation stack

Use the user's usual local stack:

- Frontend: React + Vite.
- Diagram canvas: React Flow if already available in the boilerplate/project; otherwise add it because custom graph editing is not worth owning.
- Backend: Go HTTP API + SQLite.
- Auth/workspaces: first-party email/password + workspace membership.
- Deployment: `https://endstate.ahsanworks.com` once implemented.

## API shape

```http
GET    /api/workspaces
POST   /api/workspaces
GET    /api/workspaces/{workspaceID}/projects
POST   /api/workspaces/{workspaceID}/projects
GET    /api/projects/{projectID}
PATCH  /api/projects/{projectID}
DELETE /api/projects/{projectID}

GET    /api/projects/{projectID}/diagram
PUT    /api/projects/{projectID}/diagram
POST   /api/projects/{projectID}/nodes
PATCH  /api/projects/{projectID}/nodes/{nodeID}
DELETE /api/projects/{projectID}/nodes/{nodeID}
POST   /api/projects/{projectID}/edges
PATCH  /api/projects/{projectID}/edges/{edgeID}
DELETE /api/projects/{projectID}/edges/{edgeID}
```

For MVP, `PUT /diagram` can save nodes and edges in one transaction. That is simpler and prevents half-saved graph state.
