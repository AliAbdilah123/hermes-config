# Program detail purchase surfaces + leave endpoint fix

When a Komuna program/product detail purchase or leave bug appears live, check both the React app and the active Go API under `/home/ubuntu/projects/komuna/api/v1`. The older TypeScript API may have similar tests/routes but is not necessarily the live service.

## Durable lessons

- Public routes can use slugs, but leave membership must resolve to the canonical program ID server-side before updating `program_members`.
- The live Go API route needed explicitly supporting `DELETE /api/v1/programs/:program/membership`; frontend-only tests around `leaveProgram(program.id)` do not prove live leave works.
- Archived package filtering has multiple public/member purchase surfaces:
  - program detail store/package list,
  - product detail `linked_packages`, generated by `packagesForProduct`,
  - direct checkout pages/quote paths.
- Admin/history screens may still need archived packages, so do not globally hide archived packages from every query without checking the surface.
- For product-detail package-card sizing complaints, inspect `apps/web/src/pages/product-detail/PackageCard.tsx` and `PackagesSection.tsx`; the program-detail store card may be a different component.

## Minimal verification pattern

```bash
cd /home/ubuntu/projects/komuna/api/v1
go test ./...

go build -o /home/ubuntu/projects/komuna/api/server .
sudo systemctl restart komuna-api.service
curl -fsS http://127.0.0.1:8095/api/v1/health
curl -s -o /tmp/leave.out -w '%{http_code}\n' -X DELETE \
  http://127.0.0.1:8095/api/v1/programs/<known-slug>/membership
cat /tmp/leave.out  # expect auth_required when unauthenticated, not not_found

cd /home/ubuntu/projects/komuna/apps/web
npm run build
rsync -a --delete dist/ /var/www/html/projects/komuna/
```

A `401 auth_required` from the unauthenticated leave request is a useful route-exists smoke test; do not mutate live memberships just to verify the handler unless the user explicitly permits a test account.
