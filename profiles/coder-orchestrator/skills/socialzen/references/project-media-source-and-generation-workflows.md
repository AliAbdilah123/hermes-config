# Project media source and generation workflows

Use when the Project page offers local files and generated media as ways to create the same downstream posts.

## Model the relationship before styling

- Present upload and generation as peer entry points before the shared post list.
- Use explicit `OR` language or a source selector when the routes are alternatives for one creation attempt.
- State whether users may return and use the other route later; “choose one way” can otherwise imply a permanent project-level choice.
- If “blank post” is also available, include it in the entry-point model or explain why it appears downstream. Do not claim two exclusive choices while quietly exposing a third.
- Equal entry points need equal visual weight. A filled primary button on only one route communicates a recommendation, not equality.

## Generated media is a process

Do not imply prompt → final asset when images or videos may need alterations. Make human decisions between stages legible:

1. **Brief** — goal, audience, format, references, constraints.
2. **Concepts** — compare multiple directions.
3. **Refine** — alter composition, details, style, motion, pacing, or regenerate selected parts.
4. **Approve** — retain final assets and convert each approved output into a Project post.

The interface need not show every stage simultaneously, but it must expose iteration, versioning, and approval before generated media enters the shared post list.

## Useful layout stances

- **Choice first:** equal cards for upload and generation above posts. Best for immediate clarity.
- **Guided studio:** persistent source selector beside a focused workspace. Best default when users may switch routes.
- **Production pipeline:** visible generation stages with upload as a direct bypass. Best when iterative generation is a major capability.

## Review checks

- Can a reviewer explain in one sentence how upload and generation relate?
- Is the choice scoped to one attempt, one post, or the whole Project?
- Can generated work be reviewed and altered before becoming a post?
- Are all actual creation routes represented consistently?
- Does visual emphasis match the stated relationship?
- Is the shared destination—the Project post list—clear for both routes?
